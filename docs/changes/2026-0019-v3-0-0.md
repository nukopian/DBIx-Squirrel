## Background

The design for DBIx::Squirrel on Ekorn::Pipeline as it is, record
2026-0013's, was split into six items. This one is the release: the
design's sections 10 (what changes for users, and how they move), 11
(versions) and 15 (knock-on effects on other documents). The design
itself is kept by the tag `archive/pipeline-experimental`, in
`docs/design/DESIGN.md`.

When work started, every item it depends on had shipped to `develop`,
unreleased, and Iain had signed off the documentation, putting the
project in a pre-release posture. Already done, of what the item
lists: the README, the user guide (2026-0021) and the reference, with
its table of what changes for users (2026-0023), `|` giving one value
explained where each first shows it; and the `cpanfile`'s range,
`>= v0.3.0, < v0.4.0`, moved in
80113c3e563a1a9bad97462bd91f931e2c0092ca.

Ekorn::Pipeline's release will be v0.3.1, not v0.3.0, as the item
first said: v0.3.0-TRIAL failed two of its own tests on Windows, which
expected "\n" where Windows writes "\r\n", and its fix, with
`Stop->throw` dying rather than croaking, moved the version on.
v0.3.1-TRIAL was uploaded on 2026-11-14, and DBIx::Squirrel's tests
pass against it on Perl 5.36 to 5.44. The range takes it unchanged.

CPAN's index offers Ekorn::Pipeline v0.2.0 until v0.3.1 is released,
so a DBIx::Squirrel trial before then would get only NA reports from
CPAN Testers: its dependency can't be met.

## Decisions

None.

## The plan

What: DBIx::Squirrel v3.0.0 on CPAN, requiring Ekorn::Pipeline
`>= v0.3.0, < v0.4.0`, as the design's sections 10, 11 and 15 have it.

Why: it breaks code, which a major version is for.

Steps:

1. **Ekorn::Pipeline v0.3.1 released on CPAN,** in Ekorn-Pipeline's
   session, once its trial's reports are clean.
2. **CI takes Ekorn from CPAN,** the task in `TODO.md`: the four
   "Ekorn::Pipeline from GitHub" steps go, and CI's log shows v0.3.1
   installed by the dependencies step. The file goes with the task.
3. **`Changes`:** Unreleased becomes v3.0.0's entry, its precis naming
   what breaks and how to move, from the design's section 10, read
   with the release in mind.
4. **The README's Acknowledgements** say what Claude did in this work,
   as section 15 asks; they say only "in collaboration with Claude".
5. **A v3.0.0 trial,** as MAINTAINING.md's "A trial release" says, and
   its CPAN Testers reports read.
6. **The release,** as MAINTAINING.md's "Making a release" says, each
   outward step asked for first.

Done when: v3.0.0 is on CPAN, indexed, with a signed tag on `main`
and a GitHub release.
