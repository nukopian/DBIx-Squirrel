# 2026-0060. is_stop, from DBIx::Squirrel::Stop

**Status:** shipped, unreleased

**Decisions:** None: it's 2026-0057's D3.

**Origin:** roadmap, added 2026-11-26, from 2026-0057's D3

**Started:** 2026-11-26

**Finished:** 2026-11-26

## Background

A stage that catches errors must throw a stop on, or the run won't
stop. Every stop is an `Ekorn::Pipeline::Stop`, so the documents' Part
1, which names nothing of Ekorn's, could only say to pass on any error
that's an object (2026-0055, 2026-0056). Ekorn::Pipeline::Stop has no
function to tell a stop, only the class. Iain chose, in 2026-0057's
D3, that DBIx::Squirrel::Stop export one.

## The plan

**What:** `is_stop`, from DBIx::Squirrel::Stop on request, true of any
stop, however thrown, and false of anything else.

**Why:** so Part 1's catch passes on stops alone, naming nothing of
Ekorn's.

**Steps:**

1. `is_stop` in DBIx::Squirrel::Stop, in `@EXPORT_OK`, with an `:all`
   tag, as its other modules with names on request have; its POD.
2. Tooling's `:core` holds it, as `t/28-tooling.t` asks a tag of our
   modules to hold all they export.
3. `t/04-stop.t`: true of `Stop`'s, a subclass's, `throw`'s, and one
   caught in a stage; false of a string, `undef`, '', an array and
   another object; not exported by default. `t/07-namespaces.t`
   allows a facade a function of its own.
4. The guide's and the reference's catch examples use it; the
   reference's index and both Tooling tables list it; Part 2's
   sections on a stop's class say `is_stop` is the same test;
   `scripts/manuals`.
5. `Changes`, this record and `ROADMAP.md`.

**Done when:** `is_stop` is tested, in the POD, the reference's Part 1
and index, and the guide's catch example, with a `Changes` line, and
`yath test -L t xt` passes on 5.36 and 5.44.

## What happened
